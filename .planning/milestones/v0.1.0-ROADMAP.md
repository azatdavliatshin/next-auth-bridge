# Milestone v0.1.0: next-auth-bridge — Mode A (popup-bridge)

**Status:** ✅ SHIPPED 2026-06-14
**Phases:** 1–6
**Total Plans:** 21
**Published:** npm [`next-auth-bridge@0.1.0`](https://www.npmjs.com/package/next-auth-bridge) (SLSA provenance) · git tag `v0.1.0` · GitHub Release

## Overview

Mode A (popup-bridge) cross-context authentication for Next.js / Auth.js, built foundation-first:
the `transferStore` interface designed once against two real adapters (Phase 1), the server-side
bridge/consume routes that mint and consume opaque handles (Phase 2), the client surfaces +
middleware that drive the flow (Phase 3), the canonical threat model + full roundtrip hardening
(Phase 4), a live multi-tenant Entra reference deployment proving it in a realistic enterprise-B2B
shape (Phase 5), and the publish pipeline that shipped it (Phase 6). Security tests are colocated to
the layer that produces them — every phase shipped with its mapped negative-case coverage.

## Phases

### Phase 1: TransferStore & Adapters
**Goal**: A mode-agnostic handle store with two backends (in-memory test bench + Vercel KV), security invariants proven directly against the store.
**Plans (3):** 01-01 skeleton + locked TransferStore interface + single-site code gen + contract suite; 01-02 in-memory adapter (lazy-expiry, atomic delete-on-read); 01-03 KV adapter on @upstash/redis at ./store/kv.
**Requirements:** STORE-01..06. **Completed 2026-06-05.**

### Phase 2: Bridge & Consume Routes
**Goal**: Server-side handoff — /auth/bridge mints handles only for genuinely authenticated requests; /auth/consume exchanges them for a correctly-attributed partitioned cookie; wired by a config factory.
**Plans (3):** 02-01 foundation (TransferPayload chunk-array, sanitizeNext/getAuthCookieName, cookie codec, route types); 02-02 /auth/bridge (session-gate-first 401, opaque-handle-only, chunk harvest excluding PKCE decoys, Origin allowlist); 02-03 /auth/consume (partitioned CHIPS Set-Cookie, forged/replayed→4xx) + createAuthBridge factory.
**Requirements:** ROUTE-01..06. **Completed 2026-06-07.**

### Phase 3: Client Helpers, Pages & Middleware
**Goal**: Client surfaces that drive the flow and connect to the routes; first complete iframe→partitioned-cookie flow on the Vitest bench.
**Plans (4):** 03-01 isTrustedMessage + detectContext (open-union); 03-02 runPopupFlow + createBridgeMiddleware (store/crypto-free edge router); 03-03 openAuthPopup (typed rejections); 03-04 public-surface wiring + headline E2E roundtrip + THREAT-07 URL hygiene.
**Requirements:** CLIENT-01..05. **Completed 2026-06-08.**
**Deviation (D-13):** v0.1 ships only framework-agnostic `runPopupFlow(deps)` — no React/.tsx; the popup page component lives in the Phase 5 example app.

### Phase 4: Threat Model & Roundtrip Hardening
**Goal**: The complete Mode A security story written down and proven end-to-end — every invariant has a documented entry + a passing integration test; no-token-in-URL closed at roundtrip level.
**Plans (2):** 04-01 harden roundtrip.e2e.test.ts (drive REAL openAuthPopup + runPopupFlow, replay + wrong-origin negatives, URL-hygiene sweep); 04-02 author docs/threat-model.md (THREAT-NN-keyed registry, each row property→mitigation→green test).
**Requirements:** HARDEN-01..03. **Completed (verified passed).**

### Phase 5: Multi-Tenant Reference Example
**Goal**: The bridge proven in a realistic enterprise-B2B shape — a multi-tenant Entra app on a live Vercel preview using the KV adapter — with provider-agnosticism in CI and the Mode B entry point scaffolded inert.
**Plans (5):** 05-01 tenant-app scaffold + multi-tenant Entra + createAuthBridge/KV wiring + popup page + middleware; 05-02 dynamic per-tenant manifest + inert /install-pwa "Mode B preview"; 05-03 swappable consume transport + opener sign-in + ≥2 tenant pages + separate cross-site host-shell; 05-04 browserless auth-code+PKCE Keycloak roundtrip test + GH Actions Keycloak job; 05-05 live two-origin Vercel/Entra deploy + manual CHIPS partition observation + transport decision (human checkpoint).
**Requirements:** EXAMPLE-01..04 (EXAMPLE-05 deferred to v0.1.x). **Completed (verified passed; live validation recorded 2026-06-12).**

## Milestone Summary

**Decimal phases:** none.

**Key decisions:**
- Mode A only, depth over breadth — Mode B deferred to v0.2 (matches Core Value: the security-critical handoff cannot fail).
- One shared `transferStore` (256-bit one-time codes) backs the architecture; designed against two real adapters from day one.
- `@semantic-release/git` kept (CHANGELOG persisted to `main`) with an owner-PAT push that bypasses the `main` ruleset.
- First release pinned to `0.1.0` via a `v0.0.0` baseline tag (semantic-release defaults first release to 1.0.0).
- Dedicated Edge-safe `next-auth-bridge/middleware` subpath so Next.js Edge middleware avoids the `node:crypto` graph.

**Issues resolved during the ship:** tsdown `unrun` peer-dep on clean installs; `NODE_AUTH_TOKEN` shadowing in setup-node's .npmrc; npm 2FA requiring an Automation token in CI; the Actions bot unable to bypass branch rules on a personal repo (resolved via a ruleset + owner PAT); the Edge `node:crypto` build break (resolved via the `./middleware` subpath).

**Technical debt incurred (tracked):**
- Keycloak provider-agnostic CI job can't start its service container in GitHub Actions (artifacts exist + pass locally; not a required check). Fix: run Keycloak via explicit `docker run`/compose `start-dev`.
- npm OIDC Trusted Publishing switch (Phase B) deferred to post-publish — now unblocked since the package exists.

**Deferred to later milestones:** EXAMPLE-05 (minimal popup-only example, v0.1.x); Mode B / PWA-shell (v0.2); Upstash second-adapter proof (v0.1.x/v0.2); authjs.dev recipe cross-repo PR (RELEASE-05, post-publish, source in-repo); real-host community validation (v0.1.x VALID milestone).
