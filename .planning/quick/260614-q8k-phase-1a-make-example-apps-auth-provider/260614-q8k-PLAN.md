# Quick Task 260614-q8k: Phase 1a — public Keycloak demo (env-switchable provider)

Make the two example apps' Auth.js provider env-switchable (Microsoft Entra
default | Keycloak), add a confidential `bridge-example-app` client to the
committed Keycloak realm, scaffold the hosted-Keycloak + Vercel deploy as a
runbook, and document the live demo in the README.

## Scope boundary

In-repo work (executed in full):
- **Part A** — env-switchable provider across both example apps.
- **Part B** — `bridge-example-app` client + `sslRequired: external` in
  `realm-export.json`. No secret committed.
- **Part E** — README "Live demo" section.

Out-of-repo work (cannot provision external infra / set deployment secrets from
here — delivered as an executable runbook + Docker assets the maintainer runs):
- **Part C** — host Keycloak on a persistent HTTPS service.
- **Part D** — deploy both apps to Vercel on two distinct origins.

Out of scope per brief: the `keycloak-agnosticism` CI workflow fix, Mode B / PWA,
OIDC trusted-publishing.

## Decisions (locked by brief + reconnaissance)

- Provider switch: `NEXT_PUBLIC_AUTH_PROVIDER=keycloak` → provider id `keycloak`;
  anything else (unset / `entra`) → `microsoft-entra-id`. Default path unchanged.
- Demo tenant: add a new `demo` slug to `DEMO_TENANTS` and set `DEMO_TENANT_ID=demo`,
  so the page's `tid === tenant` assertion passes for Keycloak users
  (`token.tid = DEMO_TENANT_ID ?? "demo"`). `acme`/`globex` stay (manifest tests
  reference `acme`/`globex` — untouched). Host-shell embed retargeted `/t/acme` → `/t/demo`.
- New app client uses Auth.js callback path `/api/auth/callback/keycloak` (these
  apps mount NextAuth at `/api/auth`, unlike the CI `bridge-test-client` which uses
  a custom basePath). Confidential client, no committed secret.
- `signIn` callsites (2): `tenant-app/app/t/[tenant]/sign-in-button.tsx:56` and
  `host-shell/app/page.tsx:70`.
- `middleware.ts` keys on `__Secure-authjs.session-token` (provider-independent) —
  confirmed, no change (A7).
- Threat model: this task touches example-app config + docs only — not bridge /
  consume routes, transferStore, cookie attributes, or wrapper detection — so no
  `docs/threat-model.md` update is required.

## Tasks

1. A1 — `auth-provider.ts` (`AUTH_PROVIDER_ID`) in `tenant-app/lib/` and
   `host-shell/lib/` (create `host-shell/lib/`).
2. A2 — `tenant-app/auth.ts`: import Keycloak, conditional provider, Keycloak `tid`
   fallback in the `jwt` callback. Entra `readTenantId` path untouched.
3. A3 — `host-shell/auth.ts`: conditional provider swap (no `tid` plumbing).
4. A4 — both `signIn(...)` callsites use `AUTH_PROVIDER_ID`.
5. A5 — add `demo` tenant; retarget host embed to `/t/demo`.
6. A6 — `.env.example` for both apps: add Keycloak vars + `DEMO_TENANT_ID`.
7. B — realm-export: `bridge-example-app` confidential client; `sslRequired: external`.
8. C/D — `examples/keycloak-demo/` deploy runbook + Dockerfile/compose + pin-secret script.
9. E — README "Live demo" section + TOC entry.
