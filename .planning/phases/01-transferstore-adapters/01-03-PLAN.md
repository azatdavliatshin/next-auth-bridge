<objective>
Implement the production "Vercel KV" `TransferStore` adapter on `@upstash/redis` at the `next-auth-bridge/store/kv` subpath, and prove it against the same shared contract suite (D-15) using the clock-aware FakeUpstashRedis — no real KV instance.

Purpose: STORE-03 — cross-invocation state for Vercel serverless (an in-memory store fails the roundtrip by construction on serverless). Built on the non-deprecated `@upstash/redis` client (D-10), isolated behind a subpath export with an optional peer dependency so the test bench never pulls it in (D-11). It uses the two security-critical SDK primitives — native `set({ ex })` TTL (D-08) and atomic `getdel` (D-09) — and relies on the SDK's auto-(de)serialization (resolved Open Question 1, no double-encoding).

Output: `KVTransferStore` at the `./store/kv` subpath, passing the full contract suite against FakeUpstashRedis; the subpath resolves via `tsup` build.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| adapter → @upstash/redis (HTTP) | The KV adapter trusts the SDK for atomic getdel and native EX eviction; serialization is delegated to the SDK |
| store → cross-invocation KV state | Serverless invocations share state via KV (not memory); one-time-use and TTL must hold across invocations, enforced server-side by getdel + EX |
| consumer → ./store/kv subpath | Only consumers importing the subpath pull in @upstash/redis (optional peerDep); the main entry stays free of it (dependency isolation, D-11) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-08 | Elevation of Privilege | consume() replay / TOCTOU (KV) | mitigate | Atomic `getdel` — a SINGLE server-side command (Redis GETDEL), no get-then-del window (D-09); second consume returns null. NOT a pipeline/MULTI (RESEARCH anti-pattern). Contract suite (against the fake) asserts second-consume→null and concurrent→exactly-one-wins (STORE-05 / THREAT-02). HIGH severity — blocking |
| T-01-09 | Elevation of Privilege | stale handle reuse (KV expiry) | mitigate | Native `set(key, value, { ex: ttlSeconds })` — backend evicts on TTL (D-08); ttlSeconds capped ≤60s at construction (throw on >60, D-07). The fake models EX against the injected clock so the contract suite proves expiry deterministically (Pitfall 2). HIGH severity — blocking |
| T-01-10 | Tampering | payload (de)serialization | mitigate | Rely on SDK auto-(de)serialization; pass typed object through, read via `getdel<TransferPayload>` — NO manual JSON wrapper (avoids the double-encode corruption that would silently malform the payload, Pitfall 3); KV-specific test asserts round-trip deep equality + type (resolved Open Question 1) |
| T-01-11 | Denial of Service / Repudiation | operational vs security error conflation | mitigate | D-13 error model: `null` reserved for the security miss path; genuine operational failures (KV unreachable, deserialization error) propagate as throws (bridge 5xx) — the adapter does NOT catch-and-null them, so an attacker cannot mask a backend failure as a benign miss and the bridge can distinguish retry from reject |
| T-01-SC | Tampering | @upstash/redis import | accept | Cleared by RESEARCH Package Legitimacy Audit (slopcheck [OK], 3.59M/wk, official upstash/redis-js repo, no postinstall script). Declared as OPTIONAL peerDep + devDep; no blocking human checkpoint required |

No HIGH-severity threat is left unmitigated. The KV adapter proves STORE-03/05/06 against the clock-aware fake; the real-KV roundtrip is exercised by the Phase 5 Vercel preview per the PROJECT.md constraint.
</threat_model>
