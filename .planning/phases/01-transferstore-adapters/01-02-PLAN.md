<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → in-memory store | Caller requests/consumes a code; the store must enforce one-time-use and TTL with no caller influence over entropy |
| store → process Map | Single-process memory; atomicity rests on synchronous read-delete-before-await (no cross-invocation sharing — that's the KV adapter's job) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-04 | Elevation of Privilege | consume() replay (in-memory) | mitigate | Atomic delete-FIRST then validate (D-09): read+`map.delete` execute synchronously before any await yields, so two concurrent consumes cannot both observe the entry (Pitfall 1). Contract suite asserts second-consume→null and concurrent→exactly-one-wins (STORE-05 / THREAT-02). HIGH severity — blocking; one-time-use guaranteed structurally |
| T-01-05 | Elevation of Privilege | stale handle reuse (in-memory expiry) | mitigate | Lazy `expiresAt` check on consume against the injected clock (D-08/D-14); expired → delete + null. TTL capped ≤60s at construction (throw on >60, D-07). Contract suite advances the clock past TTL and asserts null (STORE-06 / THREAT-02). HIGH severity — blocking |
| T-01-06 | Information Disclosure | miss-mode oracle (in-memory) | mitigate | not-found / expired / consumed all return `null` with no per-mode branch or timing signal (D-03); suite asserts consume-of-unknown returns null identically (no oracle) |
| T-01-07 | Tampering | stored Map entry shape | mitigate | Entry is `{ payload, expiresAt }` — no mode-discriminating field (D-06); contract suite asserts no mode key (STORE-01) |

No HIGH-severity threat is left unmitigated. The in-memory tier proves STORE-05/06 directly with no network dependency.
</threat_model>
