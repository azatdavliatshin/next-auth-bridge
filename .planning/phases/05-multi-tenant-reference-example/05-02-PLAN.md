<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public GET -> manifest route | Untrusted `tenant` path segment flows into a per-request manifest body; no secrets, no auth involved. |
| reader -> /install-pwa page | Inert scaffolding; the risk is a reader mistaking it for a working native flow (mitigated by an explicit label). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-05 | Information Disclosure | manifest route media type | mitigate | Raw `Response` with explicit `application/manifest+json`; test asserts the media type and rejects a regression to `application/json`. No secrets in the manifest body. |
| T-05-06 | Spoofing | reflected `tenant` segment | accept | The `tenant` segment is reflected only into a manifest `name`/`start_url`/`scope` (a same-origin path), never into HTML/script or a cross-origin URL; no XSS/redirect surface. Low risk for a static-shaped JSON manifest. |
| T-05-07 | Elevation of Privilege | /install-pwa inertness | mitigate | No service worker registered, no Mode B auth wired (acceptance criteria grep for `serviceWorker`); the page cannot establish any native auth state. |

Note: the manifest/install-pwa surface does NOT touch the bridge/consume routes, transferStore behavior, cookie-attribute setting, or wrapper-detection logic — the CLAUDE.md threat-model-discipline trigger is not tripped.
</threat_model>
