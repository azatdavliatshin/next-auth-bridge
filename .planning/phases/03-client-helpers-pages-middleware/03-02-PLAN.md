<objective>
Build the two Wave-1-logic helpers that depend on the shared DI fakes from 03-01: `runPopupFlow(deps)` (the framework-agnostic popup-side orchestrator — silent-auth context fetches `/auth/bridge` for `{ code }` then posts it to the opener, CLIENT-01) and `createBridgeMiddleware(options)` (the store-free, crypto-free context-routing factory, D-08/D-09/D-10/D-16, CLIENT-04).

Purpose: `runPopupFlow` is the popup half of the handoff — it forwards the bearer handle to the opener over `postMessage` with an explicit `targetOrigin` (never `'*'`), the IO complement to 03-01's `isTrustedMessage` receiver check. `createBridgeMiddleware` is the UX-only router: it chooses WHERE to route an already-unauthenticated embedded request (rewrite to the popup entry, since a full-page IdP redirect breaks inside an iframe), and NEVER WHETHER to allow access — proven both behaviourally (forged-signal invariance) and structurally (no store / verifySession / node:crypto import, keeping it Edge-safe per D-16).

Output: `popup-flow.ts`, `middleware.ts`, and their colocated tests. (v0.1 ships NO `.tsx` / React — the actual `/auth/popup` page component is deferred to the Phase 5 example app per D-13; this plan ships only the framework-agnostic `runPopupFlow`.)
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| popup → opener (`postMessage`) | The `{ code }` bearer handle leaves the popup over a cross-window channel; the targetOrigin must pin the receiver |
| client → Next middleware (`Sec-Fetch-Dest`) | A browser-set request header drives UX routing; it must never be trusted as an access decision |
| middleware → Edge runtime | The middleware's transitive import graph must stay Node-API-free to run in the Edge runtime |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 (THREAT-03/THREAT-07) | Information Disclosure | `runPopupFlow` postMessage | mitigate | Post the handle with an explicit `hostOrigin` targetOrigin, NEVER `'*'`; assert no `'*'` in source and the message carries only source/type/code (no token). |
| T-03-04 (CLIENT-04) | Tampering | `createBridgeMiddleware` Sec-Fetch-Dest routing | mitigate | Detection is UX-only: a forged `Sec-Fetch-Dest` changes only the rewrite target, never access. Behavioural forged-signal-invariance test at fixed auth state proves the security outcome is invariant. |
| T-03-05 (D-16) | Denial of Service | middleware import graph (Edge runtime) | mitigate | Structural assertion that the module imports no store / `node:crypto` / `@upstash/redis` / `verifySession` / package root — keeps it edge-safe and prevents tier coupling. |
| T-03-06 | Elevation of Privilege | middleware as a pretend security gate | mitigate | The middleware performs no session verification (delegates to the app-supplied edge-safe `isAuthenticated`); the real gate stays Phase 2 `/auth/bridge` verifySession. Structural no-verifySession assertion. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs this phase (03-RESEARCH.md Package Legitimacy Audit). Hand-rolled functions only. No slopcheck checkpoint required. |
