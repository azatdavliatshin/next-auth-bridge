<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| popup → opener (`postMessage`) | The `{ code }` bearer handle (D-01) crosses an untrusted cross-window channel; the opener must validate the sender before trusting the payload |
| embedding host → app (`window.top`) | A cross-origin parent is untrusted; accessing `win.top` may throw — the throw itself is the embedded signal |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-01 (THREAT-03) | Spoofing | `isTrustedMessage` — sender validation | mitigate | Require BOTH `event.origin ∈ allowedOrigins` AND `event.source === expectedSource`; a wrong-origin OR wrong-source message returns false (asserted by the zero-DOM negative tests). Origin-only would let a same-origin window race the channel. |
| T-03-02 (THREAT-03) | Information Disclosure | message payload trust | mitigate | The predicate gates trust before the caller reads `code`; a foreign/racing message never resolves the flow. Tested pure, zero DOM. |
| T-03-DC | Tampering | `detectContext` open union | accept | The context signal is UX-only (no security decision here); an unknown member routing to the default browser branch is the safe failure. Real auth gate stays Phase 2 `verifySession`. Forward-compat default-fallback asserted; no exhaustive switch. |
| T-03-SC | Tampering | npm/pip/cargo installs | accept | No package installs this phase (03-RESEARCH.md Package Legitimacy Audit: "no installs — not applicable"). All deliverables are hand-rolled pure functions. No slopcheck checkpoint required. |
</threat_model>
