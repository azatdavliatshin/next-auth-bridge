DECISION RECORD (resolves RESEARCH Open Q1 — @semantic-release/git vs branch protection):
This plan KEEPS `@semantic-release/changelog` + `@semantic-release/git` so the CHANGELOG is persisted
into `main` (RELEASE-01 explicitly names a CHANGELOG entry). The git plugin re-commits CHANGELOG +
the bumped version with a `[skip ci]` message. Because `main` is branch-protected (RELEASE-04), the
release workflow's `GITHUB_TOKEN` push MUST be permitted via a ruleset bypass actor — this is
documented and applied maintainer-side in Plan 04's governance doc. Rationale for keeping git over
dropping it: RELEASE-01's "CHANGELOG entry" success criterion reads most faithfully as a persisted
CHANGELOG.md in the repo, not only release notes on the GitHub Release. The bypass-actor cost is a
single documented ruleset setting, applied once. (Researcher's default leaned toward dropping git to
keep main strictly PR-only; this plan takes the keep-git path to satisfy the literal CHANGELOG
requirement, and pins the mitigation — a scoped bypass actor + `[skip ci]` loop guard — in Plan 04.)
