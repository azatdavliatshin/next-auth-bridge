<objective>
Build the commit governance and publish CI: a hand-rolled `.githooks/commit-msg` hook (D-04) with a
subprocess-driven Vitest test (RELEASE-03), the npm publish workflow with provenance (RELEASE-02),
and the PR-title Conventional-Commits check (D-05).

Purpose: This is the governance + publish layer. The local hook guards the maintainer's commits; the
PR-title check guards the squash-merge subject that semantic-release actually parses on merge to
`main` (the gap the local hook structurally cannot cover for external contributors). The release
workflow is what actually publishes `next-auth-bridge` to npm with a Sigstore attestation. All files
here are disjoint from Plan 01's files, so this plan runs in Wave 1 in parallel with the tsdown
migration.

Output: `.githooks/commit-msg`, `packages/core/src/__tests__/commit-msg.test.ts`,
`.github/workflows/release.yml`, `.github/workflows/pr-title.yml`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → npm registry | the release workflow holds NPM_TOKEN and performs the irreversible publish |
| external contributor PR → main | the PR-title check + branch protection guard what reaches the release-parsing surface |
| local commit → repo history | the commit-msg hook guards the maintainer's local subjects |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-08 | Information Disclosure / Elevation | NPM_TOKEN in workflow | mitigate | NPM_TOKEN is a least-privilege automation token stored only as a GitHub repo secret, referenced as `${{ secrets.NPM_TOKEN }}`, never echoed; the publish job is the only consumer (maintainer creates it — documented in Plan 04) |
| T-06-09 | Spoofing / Tampering | published artifact attestation | mitigate | `id-token: write` scoped to the publish job + GitHub-hosted runner + NPM_CONFIG_PROVENANCE true yields Sigstore provenance (Pitfall 2 — missing id-token silently drops attestation) |
| T-06-10 | Tampering | compromised PR alters release subject to mis-version | mitigate | the PR-title CI check (D-05) validates the squash-merge subject (what semantic-release parses) + the local commit-msg hook (D-04) guards local commits; together they close the version-derivation integrity gap |
| T-06-11 | Elevation | pull_request_target code execution | mitigate | the PR-title workflow uses pull_request_target but reads the title only and never checks out or runs PR code (Pitfall 5); permissions limited to `pull-requests: read` |
| T-06-12 | Tampering | third-party GitHub Action supply chain | mitigate | amannn/action-semantic-pull-request pinned to `@v6` (full SHA acceptable per RESEARCH); RESEARCH notes it as widely used (Vite/Vercel/Electron) |

No change in this plan touches the bridge / consume / cookie / wrapper-detection logic; these are CI
workflows + a git hook only and do not affect any runtime threat-model.md invariant. No
threat-model.md update is required.
</threat_model>
