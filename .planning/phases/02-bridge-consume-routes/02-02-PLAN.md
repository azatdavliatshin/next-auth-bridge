<objective>
Build the `/auth/bridge` handler builder: a Web-standard `(request) => Promise<Response>` closure (D-06) that enforces the core security gate — mint an opaque handle ONLY after `verifySession` confirms a real session (ROUTE-01/THREAT-04), harvest only the session-token chunks from the incoming `Cookie` header (D-05, excluding PKCE/state/csrf decoys → ROUTE-04/THREAT-05), and return `200 { code }` with zero cookies set (ROUTE-02/AM-2). Encode the failure-path decisions: `401` no-session refusal (D-07), `5xx` empty-harvest operational error (D-15), and `4xx` present-but-disallowed Origin with absent-Origin passthrough (D-12/D-14).

Purpose: This is the security-critical heart of the phase. The session gate, the no-token-in-body property, and PKCE non-interference are the invariants that "cannot fail" per the project Core Value. Every one ships with a negative test here.

Output: `bridge-route.ts` (the handler builder) and `__tests__/bridge-route.test.ts` (the full negative suite).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → /auth/bridge | The incoming request is untrusted: its Origin, its context/wrapper signals (`?popup=true`), and its cookies. Only `verifySession` (server-side, app-owned) establishes identity. |
| incoming Cookie header → harvested payload | The Cookie header is attacker-influenceable; the harvest must select ONLY session-token chunks by the resolved prefix and exclude all decoys. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| THREAT-04 | Spoofing / Elevation | session gate in `createBridgeHandler` | mitigate | `verifySession` runs FIRST and independently; a falsy result → `401` no body; no wrapper/context signal ever gates the mint. Negative test: context-signal-without-session → `401`; no-session → `401` + no handle. |
| THREAT-05 | Tampering | chunk harvest (PKCE non-interference) | mitigate | Harvest matches only session-token base + numeric suffixes; PKCE/state/csrf/callback-url decoys excluded; the success response sets ZERO cookies (AM-2). Negative test: decoy-exclusion + `getSetCookie() === []`. |
| THREAT-09 (partial) | Information Disclosure | bridge response (ROUTE-02) | mitigate | `200 { code }` JSON only — opaque 64-hex handle; no session token in body, no handle in any URL. Negative test asserts no token substring / no JWT-shaped string in the body. (Full roundtrip closure is HARDEN-03/Phase 4.) |
| T-02-15 | Denial of intended function | empty-harvest path (D-15) | mitigate | A verified session with no harvestable chunk → `5xx`, `store.create` not called — fails loud instead of minting a handle that consume would turn into zero cookies. Negative test asserts `5xx` + create-never-called. |
| T-02-12 | Spoofing | Origin allowlist (D-12/D-14) | accept (as defense-in-depth) | Present-but-disallowed Origin → `4xx`; absent Origin passes through to the real gate (`verifySession`). Documented as a complementary control, not the boundary (the boundary is `verifySession`). Tests assert both arms. |
| T-02-SC | Tampering | npm/pip/cargo installs | mitigate | Zero new packages (hand-rolled codec, structural typing). No legitimacy checkpoint required. |
</threat_model>
