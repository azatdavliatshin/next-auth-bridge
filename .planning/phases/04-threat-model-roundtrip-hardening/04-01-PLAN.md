<threat_model>
## Trust Boundaries

This phase IS the threat model — the roundtrip it hardens defends exactly these boundaries.

| Boundary | Description |
|----------|-------------|
| popup window -> opener iframe (postMessage) | An untrusted cross-window message carrying the bearer handle; any window can postMessage to the opener |
| client -> /auth/consume (302 navigation) | The opaque handle crosses to the server to be exchanged for the partitioned cookie |
| every client-constructed URL | The session token must never appear in a URL (only the opaque code may) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-04-01 (THREAT-03) | Spoofing | openAuthPopup message listener | mitigate | The roundtrip's wrong-origin/source negative dispatches an impostor message (bad origin OR source !== popupWin) through the REAL isTrustedMessage seam and asserts non-resolution via sentinel-race; a valid message still resolves |
| T-04-02 (THREAT-06) | Tampering | consume-route replay | mitigate | The roundtrip's replay negative drives a second api.consume of the same code and asserts 4xx + zero Set-Cookie (delete-first store) |
| T-04-03 (THREAT-07/09/10) | Information Disclosure | client-constructed URLs | mitigate | The preserved URL-hygiene sweep asserts no session-token value in the bridge URL or consume URL; the opaque code is explicitly permitted in ?code= (D-15) |
| T-04-04 (THREAT-06 honesty boundary) | Tampering | Partitioned Set-Cookie | accept | The pure-Node bench proves Partitioned attribute EMISSION + data flow only — real CHIPS partition enforcement is a manual/browser check (D-11), documented as an explicit boundary, not asserted here |
| T-04-SC | Tampering | npm/pip/cargo installs | n/a | No package installs this phase — zero new dependencies (RESEARCH Package Legitimacy Audit: not applicable) |
